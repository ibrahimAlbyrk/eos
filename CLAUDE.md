# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is

`Eos` is an orchestration layer over Claude Code. A persistent "orchestrator" agent decomposes a task and spawns worker agents (via MCP tools), each in its own git worktree; workers may spawn sub-workers and consult peers. A daemon supervises everything; a React 18 + Vite web UI, an `eos` CLI, and a native macOS app (Electron in `app/`) observe and control it live. State + a full event log live in SQLite (WAL) and stream out over SSE in ~100ms.

## Architecture

Clean-architecture monorepo, dependency direction `contracts → core → infra → entrypoints` (lint-enforced). Each dir is its own package — **NOT a workspace**, install per dir, cross-package imports are relative.

```
contracts/   Zod schemas + TS types — single source of truth for every IPC shape
core/        pure domain · ports · use-cases · services (zero Node imports, uses Clock port)
infra/       adapters for core ports (SQLite, child_process, chokidar, in-process backends)
gateway/     MCP permission broker (Bun)
spawner/     claude-cli (PTY) worker lifecycle: delivery, jsonl ingest, worktree (Node only)
manager/     daemon · CLI · MCP tools (tools/defs/) · backends/ · routes/ · prompts/ · services/
app/ · app/ui/   Electron desktop shell (Forge, main+preload) + the nested React dashboard (bundled into the app, loaded via eos://app/)
```

**Backend abstraction** is the central concept (`core/src/ports/AgentBackend.ts`). An agent session is reached through an `AgentBackend` adapter with a `BackendDescriptor` + `AgentCapabilities`. Three lanes:
- **`claude-sdk`** — *the default*. Drives `@anthropic-ai/claude-agent-sdk`'s `query()`; in-process, subscription-billed via an OAuth token, live streaming thinking.
- **`claude-cli`** — the original PTY lane (`spawner/worker.ts` over `node-pty`); subscription-billed; the automatic fallback when no subscription credential is present.
- **in-process metered** (`anthropic-api`/`openai`/`codex`) — disabled by default, for future non-Claude providers.

The orchestrator decomposes work and calls MCP tools (`manager/tools/defs/`): `spawn_worker({from})` runs a worker from a **worker definition**, `create_worker` defines one, `list_available_workers`/`list_active_workers` enumerate. System prompts are **assembled per-spawn** (DPI) from the central library at `manager/prompts/`, never static. Every tool call is brokered by the permission gateway (`POST /policy/decide`). User data lives in `~/.eos` (`state.db`, `policy.yaml`, `config.json`, `templates/`, `workers/`). All HTTP endpoints are in `contracts/src/http.ts` ROUTES.

## Build and development

```bash
npm run bootstrap                 # install all 8 package dirs in dependency order (contracts→…→app/ui→root)
npm run lint                      # repo root — enforces dependency direction (per-glob allowlist)
cd manager && npm test            # tsx --test across manager/* suites, core, spawner
cd contracts && npm test          # contracts/ · infra/ · core/ each have their own suite — run separately
cd app/ui && npm test             # web suite (vitest run)
cd app/ui && npm run build        # production build → dist/ (bundled into the Electron app)
cd app && npm start               # run the Electron desktop app (dev) against the running daemon
cd app && npm run make            # package the Electron app → app/out/ (see app/README.md)
```

Single test: `cd manager && npx tsx --test --test-name-pattern="config" shared/__tests__/config.test.ts` · `cd app/ui && npx vitest run match`.

Preview a prompt: `bash scripts/preview-prompt.sh <orchestrator|worker> [--provider <claude|preset>]` — renders the real assembled system prompt offline (no daemon).

Deploy: `eos build` converges only what changed (content-hash stamps; `--dry-run` to preview). `eos restart` (+`--db` wipes state). `eos help` for the CLI.

## Key design decisions

- **Branch on capabilities, never on backend `kind`.** Read `descriptor.*` / `capabilities.*` — a guard test (`backend-kind-literal-guard`) fails the suite if a `=== "claude-cli"` style comparison reappears.
- **Permission flow.** claude-cli: a `PermissionRequest` hook (`scripts/hooks/auto-allow.sh`) IS the gateway → `POST /policy/decide`. claude-sdk: the SDK's `canUseTool` routes to the same gateway. `AskUserQuestion` is **hard-denied everywhere** — the human-question channel is the orchestrator-only `mcp__orchestrator__ask_user` MCP tool (register-then-poll).
- **Permission mode + tool scope.** A worker's mode (`default`/`acceptEdits`/`plan`/`bypassPermissions`) and its definition's tool allow/deny + `editRegex` gate every call before policy.yaml. Mode is inherited from the parent chain.
- **DPI prompts.** Assembled at the spawn chokepoint from fragments selected by session facts. A fragment's `when` may gate ONLY on session-immutable facts (`role`, `isSubagent`, `isWorktree`, `workerDefinition`) — never on mutable ones (model/effort/permission/backend/git all change at runtime).
- **PTY message delivery goes through `spawner/delivery.ts`** (verified bracketed-paste → composer echo → CR → transcript ACK) — never write raw `text + "\r"`. The claude-sdk lane has no PTY and pushes structured input directly.
- **`spawner/worker.ts` is Node-only** (Bun + node-pty is broken); the **gateway is Bun**; the claude-sdk lane runs in the daemon (Node).
- **Local control plane is the unix socket.** The daemon serves the same router on `~/.eos/daemon.sock` (opened only after it wins the TCP port; mode 0600 — a UDS peer skips the loopback check, so the file mode IS the gate). Everything local that isn't a browser — CLI, MCP servers, the permission hook, workers — reaches it via `EOS_DAEMON_SOCK` and falls back to TCP when the socket is absent. Reason: a TCP call spends an ephemeral port, and once the range saturates with TIME_WAIT sockets every `connect()` on the machine fails with `EADDRNOTAVAIL` — which made a healthy daemon look dead. Health probes (`probeDaemon`) try the socket first for the same reason, and classify a failed probe as `down` vs `unreachable` instead of assuming the daemon is gone.
- **`~/.eos` is non-regenerable user data** (manifest in `manager/shared/user-data.ts`) — never `rm`/`mv` it by hand; template deletes are soft (`templates/.trash/`).
- **Don't run `eos build` / `eos restart` while developing Eos** — it restarts the daemon and crashes every running worker. Verify with lint + tests.
- **Context compaction is Eos-owned.** At the IDLE edge (`CompactionService.checkOnIdle`, ahead of the loop/report-gap/threshold watchers) a worker at/over `config.compaction.threshold` — or any worker on `/compact [focus]` — runs `core/use-cases/CompactContext`: a tool-less summarizer on the agent's own model (`manager/prompts/compaction/`) condenses the transcript, then `session.replaceContext(seed)` restarts the session seeded with the summary (pushed `shouldQuery:false`, so no turn runs). Old session is only replaced after a summary exists. While enabled, the claude binary's own auto-compaction is off (`DISABLE_AUTO_COMPACT`). The UI folds history behind the `compaction_completed` card; the nebula animation lives in `app/ui/src/views/agents/messages/compaction/`.
- **Conversation-wide lists ≠ transcript window.** The transcript pages lazily and folds at compaction, so a panel listing things from the whole chat (subagents, artifacts, …) must never derive from the loaded window alone: read `useConversationBlocks` (fetches the missing rows once, re-parses with the window) and widen `selectSubagentRows` (`manager/routes/subagent-events.ts`) to keep the rows the new list needs.
- **Code-view terminals on the phone.** The daemon launches Claude in Code-view PTYs (`POST /pty {claude:{}}` → `manager/services/pty/claudeLaunch.ts`) with inline hooks that report the session id and any open AskUserQuestion/ExitPlanMode call back through OSC 7777. The phone (iOS Terminals) reads the pane's transcript as worker-event rows (`GET /pty/:id/conversation`, `pending` = open dialog), sends prompts/answers as keystroke sequences verified against Claude Code's TUI (`claudeKeys.ts` — re-verify when the TUI changes), and gets raw output only after a `sub` frame. Phones never resize a PTY; phone-opened panes are adopted by the desktop workspace.
- **Accounts (Settings › Accounts).** Per provider: an optional subscription sign-in + an optional API key. The rule lives in `core/src/domain/billing-route.ts`: signed in → subscription, always (the key is never exported alongside it); expired → blocked (no silent fallback to the metered key); else the key. **Only Eos's own sign-ins count**: each CLI keeps its login under `~/.eos/accounts/` — Claude via `CLAUDE_SECURESTORAGE_CONFIG_DIR` (passed to every claude child Eos runs — agents, summarizer, Code-view panes — so it reads only the Eos store while `~/.claude` settings stay shared; plain terminal panes keep the user's own login), Codex via `CODEX_HOME`, Gemini via `GEMINI_CLI_HOME`; a Claude Code / Codex / Gemini CLI login elsewhere on the Mac is ignored for status, billing and usage. Claude sign-in drives the official `claude auth login` in a one-shot PTY (`manager/services/accounts/`) into that store (full scopes, so usage is readable; a lapsed access token is renewed through the binary's refresh-token login before a usage read). A legacy `config.anthropic.authToken` setup-token still bills until the next sign-in/out clears it. ChatGPT sign-in drives the official `codex login` (writes Eos's `CODEX_HOME`; not the app-server's `account/login/start`, whose page stalls after the account pick because it names Eos as the client) and runs on the **`codex-cli` lane** (`manager/backends/codex/`): the user's Codex CLI `app-server` over JSON-RPC, one process + thread per session, read-only sandbox + `untrusted` approvals so every command/patch is decided by the policy gateway as Bash/Edit/Write; Eos tools reach it via the stdio `orchestrator-mcp`/`worker-mcp` servers. While signed in to ChatGPT the picker offers the Codex lane instead of the OpenAI API profile. Settings › Usage + the account menu show every signed-in plan's limits (`UsageService` providers: Claude's OAuth usage endpoint, ChatGPT's `account/rateLimits/read` via `CodexUsageProvider`); a not-signed-in provider is a quiet error the UI hides. Google sign-in is the Gemini CLI's own "Log in with Google" (writes under Eos's `GEMINI_CLI_HOME`), driven over ACP (`authenticate`), and runs on the **`gemini-cli` lane** (`manager/backends/gemini/`): the user's `gemini --acp`, one process + ACP session per worker, `--approval-mode default` so every command/edit comes back as `session/request_permission` → the policy gateway as Bash/Edit/Write (always one-off answers); Eos's MCP servers are pre-approved by a `--policy` file; DPI rides a fresh session's first prompt (ACP has no system-prompt channel). It reports no plan usage. `/api/accounts` + `/api/sign-ins/:id` are ui-token gated and redacted; the UI state is `app/ui/src/state/accountsStore.js`.
- **Side panel: new tab + pages.** `+` opens a `newtab:N` launcher (`app/ui/src/views/newtab/`) that turns into what it opens via `ui.replaceTab` — an address/search queues the URL for the browser panel (`queueUrl`), tools open their tab, `#`/`@`/`?` find pages/files/ask the agent; Suggested is per-viewer browser history (`browserHistoryStore`). **Pages** are markdown notes in `~/.eos/pages/<id>.md` (YAML frontmatter, user data — not state.db, so `--db` never wipes them), per project folder + optionally linked to a chat; one write path `core/src/services/PageService.ts` (rev bump + `pages:change` SSE). The UI saves full bodies with `baseRev` (409 → line-based 3-way merge, `lib/pageMerge.js`); agents use targeted ops (`/api/pages/:id/edit`: append / replace / setTask) through the `list_pages`, `read_page`, `create_page`, `append_to_page`, `edit_page`, `set_page_task` tools on both MCP servers. The editor is CodeMirror over markdown with live-preview decorations (`views/pages/editor/`). **Changes tab** (`views/agents/gitdiff/`) defaults to the *uncommitted* scope (working tree vs HEAD); the scope menu also offers *branch* — `/fs/changes?base=auto|<ref>` diffs the working tree against `git merge-base HEAD <base>` (auto = origin/HEAD, else main/master; unresolvable → plain HEAD diff, `baseLabel` null) — / a commit / a stash. Line comments and "Ask for review" (`review` worker action) go to the agent; diffs over 1000 changed lines page one file at a time.
- **Profile & memory (who the user is, for every agent).** User data in `~/.eos/profile/` (`profile.json`, `avatar.*`, `memories/<id>.md`; survives `--db`). One write path each: `core/src/services/UserProfileService.ts` (`profile:change`, 409 on stale `baseRev`) and `UserMemoryService.ts` (`user-memory:change`), whose narrow faces — reader / suggestion sink / editor — are what callers depend on. `core/src/services/render-user-profile.ts` is the ONLY place profile + always-on memories become prompt text: it fills `{{USER_PROFILE}}` in both preambles at spawn (empty profile ⇒ the stock `<user_preferences>` text, byte-identical) and in the focused fragment (`role/focused/01-user-profile`, empty profile ⇒ nothing, only the memory-tool section), drops lines the session already gets from CLAUDE.md, overflows past `budgetTokens` into a `search_memory` hint, and backs `GET /api/profile/preview` so "What agents see" is the real block. Prompts are fixed at `start()`: edits reach new/resumed sessions only. `sharing.withholdFrom` (backend kinds, data) gives a lane the stock text and 403s its memory tools. Agents only suggest (`suggest_memory`, deduped, capped per producer); keep/edit/delete are ui-token routes. Instructions are Eos-owned — CLAUDE.md is never written. Plan: `docs/profile/00-PROFILE-PLAN.md`. Names are `UserProfile*`/`UserMemory*` — `Memory*` already means Claude Code's file memory. Dismissing keeps a `dismissed` tombstone so no producer re-suggests it. **Dreaming** (`profile.dreaming`, off by default; nightly 03:00, Opus): `manager/services/DreamService.ts` (60 s tick; guards: Eos Claude sign-in, plan usage under `usageCeiling`; a top-level chat going WORKING stops a scheduled dream) runs `core/use-cases/DreamOverChats`, which COUNTS durability instead of guessing it: recall per finished root chat after its watermark notes signals, not traits (`prompts/dream/recall-*`); code drops product/codebase, one-task and accepted-option signals (`filterSignals`); one match call files the rest into a candidate ledger that outlives the night (`core/domain/dream-ledger.ts`; support counted per chat-and-day occasion, ready on a standing rule the user's own words ground, ≥ 2 chats on ≥ 2 days, or an irreversible-action gate; 30-day fade); only ready candidates reach one consolidation (≤ 3 proposals, NOOP by default, memories written as rules that open with their situation — `lintMemoryText`), then a separate critic call must vouch for each (`prompts/dream/critic-*`); survivors file `new/update/merge/promote/retire` proposals with evidence, support and why through the same suggestion sink (all dreams share one pending cap); keeping applies the change (`UserMemoryService.approve`). Runs, watermarks, chat exclusions and the ledger live in state.db (`061_dreams`, `063_dream_candidates`, regenerable). `bash scripts/dream-eval.sh` replays past keep/dismiss decisions through the critic. Review UI: the journal atop Memory (`views/memory/DreamJournal.jsx`) + one-at-a-time review (`components/profile/DreamReview.jsx`); plan `docs/profile/10-DREAMING-PLAN.md`.
- **Sync (one user, several Macs).** Settings › Sync: profile (minus `dreaming`), avatar, memories, pages, `~/.eos/templates`, `~/.eos/workers` follow the user to every Mac holding the same **sync key** (`eos-sync1.<relayUrl>.<secret>`; the key is the account, `~/.eos/sync/identity.json` 0600, routes LOCAL_ONLY). Each Mac pushes to / pulls from an end-to-end encrypted **vault** on the relay (`relay/vault/`, SQLite on a Docker volume; compare-and-swap per record, one seq per vault, long-poll) — the relay sees only HMAC'd keys + AES-GCM blobs, and a Mac that was off catches up from it. Engine `core/src/services/SyncEngine.ts` (index of `{seq, local hash}` per record in `~/.eos/sync/state.json`; records carry no sync fields; applied changes are re-indexed so they never echo; same record changed on two Macs ⇒ newer `changedAt` wins, the loser goes to `~/.eos/sync/conflicts/`; a never-synced local record counts as oldest, so joining adopts the account's copy). Domains (`manager/services/sync/`) write only through each data's own write path (`applySynced`/`removeSynced`, memory events `by:"sync"` — no suggestion banner on the receiving Mac); project paths travel as git-remote keys (`project-keys.ts`). Plan: `docs/sync/00-SYNC-PLAN.md`.
- **File transfer between Macs (Transfer tab, `send_to_machine`).** Every daemon serves its own disk as an endpoint, `/transfer/*` (`infra/src/transfer/FsTransferEndpoint.ts`; ui-token, so from another Mac only as the user): list, scan (manifest: tree, mode, mtime, symlinks), ranged read, offset-checked chunk write into `<dest>/.eos-incoming/<id>/` staging, commit (links last, modes/mtimes, Replace → Trash / Keep both `name 2.ext` / Skip, resumable via `placed.json`), abort, project key ↔ path. The engine runs only on the Mac the user sits at (`manager/services/transfer/TransferService.ts` over core's `runTransfer`): this Mac's endpoint in-process, a host's via `PeerEndpoint` on the link (it vouches `x-eos-peer-human`); chunks ~1 s of throughput (so request timeouts, relay→direct upgrades and the 6 s PING never bite), resume from the staged size, one transfer per paired Mac, `transfer:change` SSE, `062_transfers` (regenerable), banner on done/failed (`route: "transfers"`). Default destination: the same project on the other Mac by git remote (`projectKeys.findPath`), else `~/Downloads/Eos`. `/api/transfers*` and `/workers/:id/transfers*` are local-only. UI: `app/ui/src/views/transfer/` (store `state/transfersStore.js`, `lib/transferClient.js`); inside a host view it talks to this Mac's engine through the shell's `eosTransfer` bridge (`app/src/main/transfers.ts`) — only for views running this Mac's bundle, the other side is always the view's host, and this Mac's paths come only from native pickers. A **focused** session gets `send_to_machine` (registry `focusedDefs`, `role/focused/02-machines`): this Mac → the named Mac's `~/Downloads/Eos`, never replacing; the transcript card follows the transfer live. Plan: `docs/transfer/00-TRANSFER-PLAN.md`.
- **Phone control while the Mac is locked.** While remote is armed the daemon holds `caffeinate -s -w <pid>` (`manager/remote/keepAwake.ts`): system sleep is blocked on AC power only, the display still sleeps and locks, and a dead daemon releases it. Lid close without clamshell mode still sleeps — no user-space fix. `RelayConnector` reads a wall-clock jump between 5s ticks as a wake and redials at once. The lock visual is a real macOS screen saver (`app/saver/` → `Eos.saver` via `scripts/build-saver.mjs`, installed/started from the tray menu) with "require password immediately" — never a fake full-screen window.
- **Eos ↔ Eos (controlling another computer).** Every daemon has one identity — a self-signed cert under `~/.eos/peer/` (fingerprint = id, `deviceId` = its short form) — and plays both roles. *Hosting* (Settings › Remote access, `config.peer`, off by default): `PeerHostService` serves HTTP/2 over TLS 1.3 with both certs pinned, on a direct port (7402) and through its own relay room; pairing is a single-use invite link (`eos://pair/…`) that never expires on its own — open ones persist (hashes only, max 3) until used or cancelled, and 5 wrong secrets burn them all. *Controlling* (Machines): `HostLinkService` keeps a background `HostLink` per paired host (races direct addresses then the relay, PING = latency, moves relay→direct when it can, stops on a GOAWAY refusal). The daemon's facade `/h/<hostId>/…` IS that host's daemon: each request rides the link and the host's gateway replays it on its own unix socket/raw port — so all routes, SSE and Range work unchanged. Never forwarded: `contracts/src/route-planes.ts` LOCAL_ONLY_ROUTES. Only the user's dashboard crosses: the facade (and the host's gateway, again) refuses a caller without this Mac's ui-token or that host's view token, except the public `PEER_OPEN_ROUTES` (`/api/host`, `/ui/*`), and judges the dot-normalized path; the host attaches its own ui-token only for such vouched requests — an agent on one Mac gets no reach on the other. View tokens are an HMAC of the ui-token + host id (they survive a daemon restart), and each host view's session adds its token to every request for its prefix (`<img>`, `EventSource`, pdf.js can't). The app shell shows each host in an isolated `WebContentsView` in the same window (own partition, CSP pinned to that host's prefix, no local-path bridges), running the host's own UI bundle (`GET /ui/*`). `/stream` is resumable (`id:` + ring + `?since=`/`resync`), which is what makes a dropped link gapless. *Both ways*: a pairing can be mutual (Connect sheet "Let it control this Mac too" → `PairRequest.reciprocal`; the host adopts the device as a host, the device allows the host only once it answers `reciprocal:true` — `manager/peer/pair-mutual.ts`). When only one side can dial, the side that can offers a **reverse tunnel**: a `POST /peer/reverse` stream inside its live link is a Duplex the other side dials TLS through (route `reverse`, pinned and admitted like direct/relay; never offered over a reverse link; `/h/…/peer/*` is refused). Dial failures are classified (`manager/peer/dial-failure.ts`): `local-network` = no route to a LAN address, usually macOS Local Network privacy — launch agents aren't exempt, so the packaged daemon's plist sets `AssociatedBundleIdentifiers` and the app ships `NSLocalNetworkUsageDescription`.
- **Liquid glass (UI material).** Glass is an accent, not a theme: floating layers + interactive states only; palette unchanged. `app/ui/src/styles/glass.css` (imported last) holds the tokens and the floating-surface recipe, applied by class list (`.glass-pop`, menus, popovers, modals, toasts): blur + tint on `::before`, gradient rim on `::after` — never `backdrop-filter` on the host (it would become a backdrop root and nested glass goes blank), never animate a glass host's `opacity` (hosts rise with `translate`/`scale`). Scroll containers carry the glass on the host instead. Hover/selected fills use `--lg-chip-*` in place. Docked sidebar = quiet near-opaque glass (`.side`, pointer light via `--sy`); the composer floats over the transcript (which pads by `--composer-h`) with `components/glass/GlassLayers.jsx`: ybouane/liquidglass "Frosted Glass" (also the scroll-to-bottom drop; other presets — Clear, Dark — kept unused in `lib/liquidGlass.js`) — its WebGL shader ported to per-size maps (cached per size, built before paint) that drive a `backdrop-filter: url(#svg)` (backdrop refracted sharp + blurred via per-channel `feDisplacementMap`, mixed as the shader does) + an image drop shadow; Chromium only. ⌘B toggles the sidebar (animated grid collapse).
- **Notifications go to macOS.** Daemon `notification:fire` (ask_user "Input needed", orchestrator `notify_user`, a policy `ask` → "Approval needed" via `manager/services/permission-ask-notify.ts`, a top-level agent's WORKING→IDLE → its name + last reply excerpt via `manager/services/turn-end-notify.ts`, a controlled host's own) → `app/src/main/notifications.ts` → native banner with Eos's sound (`app/build/eos-notification.aiff`, shipped in Contents/Resources; a dev `npm start` falls back to the default sound), only while the window isn't focused; click opens the worker. UI `notify.warning/.error(message, opts?)` (`app/ui/src/lib/notify.js`, callable from React and non-React code) ride the same path through the preload `eosNotify` bridge (withheld from host views); `notify.info` is silent. No in-app toasts (`toastStore`/`ToastViewport` are unmounted).
- **Visual answers (generative UI).** Orchestrators and focused sessions — never workers — get `present`, `present_app`, `find_places`, `current_location` (registry `orchestratorDefs` + `focusedDefs`; DPI `role/orchestrator/17-present` / `role/focused/03-present`, `{{GENUI_LEVEL}}` from settings `genui.level` at spawn; a focused session runs with Claude Code's tool search on, so `present` is `alwaysLoad` — its catalog is in the prompt from turn 1 — while the other three stay deferred with a `searchHint` and the focused fragment names them `mcp__worker__*` + says to ToolSearch them; orchestrators load every tool directly via `ENABLE_TOOL_SEARCH=false`). Three tiers: text stays the default; a **view** (`present {title, tone, icon, replaces, data, actions, ui, summary}`) holds entities once in `data` and a JSX-like `ui` string of catalog components that only reference it (lenses), rendered natively from Eos's kit; an **app** (`present_app`) is agent HTML in `<iframe srcdoc sandbox="allow-scripts allow-forms">` (opaque origin, CSP `connect-src 'none'`, images data:/blob: only; `window.eos` bridge = an MCP Apps subset, every send and link confirmed by the user; the frame mounts only once the daemon stored the app). The catalog, entity/action schemas, limits, `validateView`, the markup / partial-JSON / expr parsers and `catalogPrompt()` (injected into present's description, so docs can't drift) live in `contracts/src/genui/` — markup/partial-json/expr/attrs are dependency-free and imported by the UI. `core/use-cases/PresentView` validates and mints `v_<12 base62>` into `genui_views` (`064_genui_views`, regenerable); routes `manager/routes/genui.ts` (state PUT is ui-token + `genui:change`). The claude SDK lane streams the tool input as bus topic **`genui:delta`** (never `agent:delta`, which LiveText/iOS read), focus-filtered like it; other lanes render on the finished call. Media: `/api/genui/media/{img,og,icon}` and `/api/genui/map/*` (OpenFreeMap dark via MapLibre, tiles proxied, never prefetched) are ui-token gated — the app shell adds the token to subresource loads only, navigations are refused — and fetch through an SSRF guard (`infra/src/genui/net-guard.ts`, `safe-fetch.ts`) into `~/.eos/media-cache` (regenerable); geocode = Nominatim (1 rps), `find_places` = Overpass. Location: `GET /api/location` (LOCAL_ONLY) asks the app over the browser-host RPC (`location.get` → the CoreLocation helper `EosLocation.app` (`app/location/main.swift` + `Info.plist`, built by `app/scripts/build-location.mjs` into Contents/Resources; main runs its `Contents/MacOS/eos-location` directly) — Electron's `navigator.geolocation` never reaches CoreLocation; locationd keys the helper by its own identity `com.ibrahimalbyrk.eos.location`, so its prompt and Location Services row are its own; it must be a bundle — CoreLocationAgent silently skips the prompt for a bare binary, even one with an embedded `__info_plist`), answers only the dashboard (ui-token) or an orchestrator/focused caller, 403 unless `location.share`; every `genui.*`/`location.share` key is writable only via the ui-token `PUT /api/settings/genui` (the flat `PUT /api/settings` refuses them). Send-actions post `…/message {text, action}` → the model reads `[view action] <label>` + a JSON line, the chat shows a reply chip. UI: `app/ui/src/genui/` (ViewBlock, streamStore, runtime/, kit/<group>/, apps/, panel/ = the `view:<id>` side-panel tab). **CORS:** the API server answers only `eos://app` and its own loopback origins; any other `Origin`, `null` included, gets 403 before the route runs, and a `Host` that isn't a loopback name (DNS rebinding) is refused too (`manager/middleware/cors.ts`). Plan: `docs/genui/00-GENUI-PLAN.md`.

## Style notes

- Comments only when *why* is non-obvious. `safeStringify()` over raw `JSON.stringify()`. `e instanceof Error ? e.message : String(e)` in catch blocks.
- Code/CLI output in English; user web messages may be Turkish. Public repo — no claude.ai session trailer in commits.
- Config is deeply frozen after load; mutate by writing `~/.eos/config.json` then `container.reloadConfig()`. Node strip-only TS: no parameter properties.
